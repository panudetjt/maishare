# ให้ sender รู้ตัวว่าข้อความ/ไฟล์ไหนที่อีกฝั่งอ่านไม่ได้

**ปัญหาที่พบ (จากการไล่โค้ด):** back-channel มีอยู่แล้ว — receiver เปิด sealed frame ไม่ได้จะส่ง `undecryptable` กลับมาแบบ plain (room-client.ts `notifyUndecryptable`) แต่ฝั่ง sender ได้แค่ **toast 4 วินาที** ที่ (1) จางหาย ไม่มีร่องรอยค้างใน timeline (2) ไม่บอกว่าข้อความ/ไฟล์ไหน (3) เด้งแค่ครั้งเดียวต่อ connection (latch `undecryptableWarned`) และ receiver **ไม่มีทางรู้ id ข้อความ** เพราะ frame ที่อ่านไม่ได้ยังเข้ารหัสอยู่ — ดังนั้นการระบุข้อความต้องทำฝั่ง sender ซึ่งรู้ว่าอะไรถูกส่งแบบ sealed ไปหา peer ที่ยังไม่พิสูจน์กุญแจ

**หลักการ:** sender จด id ของทุก payload ที่ส่งแบบ sealed ไปหา peer ที่ `!proven` (กลุ่มเดียวที่มีสิทธิ์รายงานว่าอ่านไม่ได้) — พอได้รับ `undecryptable` จาก peer นั้น จึง stamp badge ลงข้อความ/ไฟล์ชุดนั้นพอดี แล้วเติม system bubble ถาวรที่ระบุชื่อ peer + ทางแก้

## 1. `src/lib/p2p/protocol.ts`

- `undecryptable` frame เพิ่ม `kind?: "frame" | "chunk"` (optional — เวอร์ชันเก่าไม่ส่ง/ไม่อ่านไม่พัง) ให้ sender รู้ว่าเป็นข้อความหรือไฟล์ที่เสีย

## 2. `src/lib/p2p/room-client.ts`

- **`PeerCtx`** เพิ่ม `sealedChats: Set<string>` / `sealedFiles: Set<string>` — id ที่ถูก seal ส่งหา peer นี้ขณะยังไม่ proven (init ตอนสร้าง ctx, clear เมื่อ pong-proof ผ่าน — frame หลังพิสูจน์อ่านได้แล้ว)
- **`sendChat`** loop ต่อ peer: ถ้า `this.cipher && !ctx.consented && !ctx.proven` → `ctx.sealedChats.add(msg.id)` (path withheld ไม่จด เพราะยังไม่ได้ส่ง)
- **`enqueue`** (จุดที่ file-queued/file-start ออกต่อ peer): เงื่อนไขเดียวกัน → `ctx.sealedFiles.add(view.id)`
- **`pong` handler** (จุด `ctx.proven = true`): clear ทั้งสอง set
- **`notifyUndecryptable`**: ใส่ `kind` ลง back-channel frame
- **handler `undecryptable` ฝั่ง sender** (ตอนนี้มีแค่ toast):
  - คง toast เดิมไว้ (ความเร็วทันที)
  - ถ้า `detail === "sealed"`: stamp — เดิน `ctx.sealedChats` patch ChatMsg ด้วย `unreadableBy` (รวมชื่อแบบ unique, update แบบ immutable ตาม convention ของ chats) และ `ctx.sealedFiles` patch TransferView ด้วย `unreadableBy`
  - เติม **system ChatMsg ถาวร** (สไตล์ `bubble-system` เดิม, แสดงในนาม peer ผู้รายงาน): kind frame → "⚠︎ {name} couldn't read your recent messages — they don't have the room key. Share the key or resend once they do." / kind chunk → ตัวแปรข้อความไฟล์; กรณี malformed/orphan คง toast เดิม ไม่ stamp
  - ถ้า set ว่าง (report มาแต่ไม่มีอะไรถูกส่งแบบ unproven-sealed) → ได้แค่ bubble + toast ไม่มี badge (ไม่ตกหล่นข้อมูล แค่ไม่เดาเกิน)
- **type**: `ChatMsg.unreadableBy?: string[]`, `TransferView.unreadableBy?: string[]`
- latch ต่อ connection คงเดิม (กัน storm) — ข้อความที่ส่ง "หลัง" report ขณะ peer ยัง unproven จะไม่โดน stamp (เอกสารไว้ว่าเป็น bound ที่ยอมรับได้ system bubble อธิบายสถานการณ์อยู่แล้ว)

## 3. `src/lib/timeline.ts`

- `TimelineMessage.unreadableBy?: string[]` — union ชื่อจากทุก part (text + files) ของกลุ่ม

## 4. `src/components/Conversation.tsx`

- **msg-head**: ถ้า `message.unreadableBy?.length` → badge ⚠ สีเตือน (คลาสใหม่ `.msg-warn` สไตล์ใกล้เคียง `.msg-lock.is-open`) title = "Not readable by {names} — they don't have the room key"
- **FileRow**: สถานะ done ที่มี `unreadableBy` → ขึ้น "sent — unreadable by {names}" สีเตือนแทน/ต่อท้าย "sent"
- ระบบ lock icon เดิมไม่แตะ

## 5. เทสต์ (ไฟล์ใหม่ `room-client.undeliverable.test.ts` ต่อยอด harness + เสริม timeline.test.ts)

- keyed sender + capable peer ที่ยังไม่ proven: sendChat ออก sealed frame → feed `undecryptable{detail:"sealed", kind:"frame"}` กลับ → chat โดน stamp `unreadableBy`, มี system bubble, tracking set มี id
- ไฟล์: sendFiles ขณะ unproven → report kind "chunk" → TransferView โดน stamp
- pong-proof ผ่าน → set ถูก clear → report ภายหลังไม่ stamp ข้อความที่ส่งหลัง proof
- report ตอน set ว่าง → ไม่ stamp แต่ยังมี bubble
- frame บน wire มี `kind` (จับจาก captured bytes ฝั่ง receiver)
- timeline.test.ts: รวม unreadableBy จากหลาย part ได้ถูกต้อง
- รัน `vp check` + `vp test` ให้ชุดเดิม (247+8) เขียวด้วย

## 6. เอกสาร

- `SECURITY-SPEC.md` SEC-01: เติม 1 บรรทัด — "unreadable deliveries surface back to the sender with per-message unreadableBy badges + a persistent system bubble (never silence, both directions)"

**Edge ที่ครอบ:** wrong-key member (ไม่มีทาง proven → stamp ได้ครบ), consented peer (รับ plain อ่านได้ → ไม่จด), peer หลายตัว (stamp เฉพาะชื่อผู้รายงาน), ข้อความยาว asText (เป็น transfer → stamp ผ่าน sealedFiles, badge โผล่ผ่าน timeline aggregate)
